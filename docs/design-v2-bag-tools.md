## v2.1 钓鱼（已实现）

按原设计落地，有三处调整：

| 设计稿 | 实际实现 | 原因 |
| --- | --- | --- |
| 收线打 `reel` | 收线打**鱼名**（`carp` / `sturgeon` / `koi`） | 鱼名长短天然对应稀有度，一份数据两用 |
| 咬钩窗口 1.2 秒固定 | 铜 1.2s / 银 1.45s / 金 1.7s / 秘银 1.95s | 让钓竿升级有可感知的手感变化 |
| 未提星级 | 按反应速度给 1~5 星 | 否则钓鱼与「打字质量」这条主轴脱节 |

等待咬钩期间玩家不能移动，`Esc` 可以收竿。抛竿太早不惩罚，只提示。

## v2.2 词库分层（已实现）

用户反馈两点：词不必与内容相关；后续要能换词库；按价值估词长的方向可行。

于是把「打什么词」抽成独立一层 `words.ts`：

| 原则 | 实现 |
| --- | --- |
| 词义与玩法解耦 | 动作只传「类别 + 难度档」，不传词 |
| 长度即难度即价值 | `bandForValue(价值)` → 7 个长度档（3~14 字母） |
| 自定义归入自动分档 | 按词的实际长度归入档位，用户不用手工分级 |
| 自定义优先 | 某分类一旦启用自定义词库，内置词不再掺入 |

**被推翻的旧设计**：v2.1 用鱼名当收线词，稀有度被词义绑死，换词库时会全乱。现改为按鱼价取难度档。

## v2.3 词库打磨（已实现）

v2.2 用「字母数」当难度，审下来有三个真问题，这轮一起修：

| 问题 | 修法 |
| --- | --- |
| **长度 ≠ 难度**：`zzzz` 和 `plow` 同为 4 字母，但连按一键容易十倍 | 引入**难度分**：字母数为基础，重复字符/低多样性减分，同手连击/罕见字母加分。分档与时限都改用难度分 |
| **档位覆盖有洞且回退静默**：割草「轻松」档曾是 0，自定义小词库会悄悄压平价值曲线 | 词库界面加**档位覆盖表**（每类×每档词数，空档标红）；保存自定义词库前给**难度分布预览**；补内置词填洞 |
| **重复疲劳**：只避开上一个词，小词库来回就那几个 | 取词改**洗牌袋**（一轮内不重复）+ 最近 8 词避让 |

难度分校准：正常词 ≈ 字母数；`zzzz`=1.15、`plow`=4.5、`water`=6。时限按 `难度分/字母数` 缩放（0.5~1.4 倍），同为 4 字母的 `zzzz` 比 `plow` 少 34% 时间。

**被推翻的旧设计**：v2.2 的「长度即难度」。长度只是难度的代理，真实手感还取决于键位。

## Steam 桌面化决策（已定，接缝已留）

用户后期要上 Steam。结论：**核心栈不换，只换壳 + 留平台接缝**。

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 是否重写引擎 | 否 | Canvas 2D + 零素材 + 零网络，任何 Chromium 壳直接跑；重写 = 丢弃全部代码 |
| 目标平台 | 仅 Windows | 免 Mac 公证 / Linux WebView 差异 |
| 桌面壳 | Electron | 纯 JS、零渲染输入风险、steamworks.js 成熟；Tauri 更小但要碰 Rust |
| 时机 | 先留接缝，玩法定型再包 | 不挡动物/四季开发 |

**本轮已做**：`src/platform.ts` —— 运行时探测 + `StorageAdapter`。把 game.ts / words.ts 里 5 处 `localStorage` 全部收口。浏览器走 localStorage，桌面由 preload 注入 `__FARM_DESKTOP__.storage` 接管为文件存档。

**关键认知**：上 Steam 的真正工作量不在壳，而在 **存档文件化**（Steam 云同步的前提）+ Steamworks 接入 + 打包管线 + 商店素材。接缝现在留，就是为了以后套壳时不用翻散落的存储调用。

**同步接口取舍**：`StorageAdapter` 现为同步。存档只在睡觉/出货/购买等低频时机触发，桌面阶段可用小型同步桥；若日后要异步，改动也集中在 platform.ts + 这 5 个调用点。

## v2.4 动物系统（已实现）

用户拍板：鸡 + 牛、完整心情系统。核心命题：**动物 = 每天必做的小事**，补上「浇水 → 睡觉」之间的空档，和钓鱼互补（钓鱼考反应、动物考照料）。

| 设计点 | 实现 |
| --- | --- |
| 阵容 | 鸡 600G 产蛋 70G / 牛 2200G 产奶 160G，各限 6 只 |
| 建筑 | 地图下方鸡舍 + 牛棚 + 围栏，动物有界随机游走；棚舍实心挡路 |
| 照料动作 | 喂食 / 捡蛋 / 挤奶 / 抚摸，新增 `animal` 词库分类；挤奶是三连短词 |
| 心情 → 品质 | 心情 0~100 每 25 点一星，完美打字再 +1；喂食 +8、抚摸 +6、饿过夜 −15 |
| 产物节奏 | 喂了今天 → 明天才有产物；新买动物带一份「见面礼」引导上手 |
| 交互 | 动物是游走实体，用「面朝方向 proximity」判定，而非地块格子 |

**与既有系统的接法**：
- 产物走 `items.ts` 的 `product` kind，和作物 / 鱼一样在出货箱卖（`isSellable`/`sellPrice` 复用）。
- 照料动作复用 `TypingSession`，`Pending.kind` 扩展 `feed/collect/milk/pet` + `animalId`。
- 睡觉时 `settleAnimalsOvernight` 统一结算，和作物生长并列。
- 背包加「产物」标签；图鉴 / 帮助 / 订购箱同步补动物。

**迁移**：`normalizeState` 给旧存档补 `animals: []` 与新统计项，老存档无缝升级。

**地图调整**：把原落在畜栏区的树 / 石 / 花迁到右侧空地，杂草生成排除畜栏区（`inAnimalArea`）。

## v2.5 四季（已实现）

用户拍板：反季长得慢（×2）、每季 8 天、节日后置。核心命题：**给经营加时间维度**，把「种什么只看利润」变成「什么季节种什么」。

| 设计点 | 实现 |
| --- | --- |
| 季节结构 | 一年 32 天每季 8 天，`seasonOfDay(day)` 推导，存档只记天数 |
| 作物适季 | `CropDef.season`；春萝卜/土豆/草莓、夏番茄/玉米、秋卷心菜/南瓜、冬菠菜（新增） |
| 反季生长 | `Plot.growth` 累积 0~1，当季每晚 +1、反季 +0.5，满 1 进一阶段；跨夜保留进度 |
| 季节视觉 | `PALETTES` 四套色板，换季 `applySeason` 重绘底图；冬不开花、树冠变色 |
| 季节天气 | `rollWeather(season)`：春雨 35% / 夏 15% / 秋 20% / 冬雪 40%；`weatherWaters` 雨浇灌、雪不浇灌 |
| 提示 | HUD 季节徽章、商店适季标签、换季弹窗、反季播种提醒 |

**关键取舍**：
- 反季用「生长累积」而非改 `days`，保住既有 stage 体系，旧档 `growth` 缺省按 0 无缝迁移。
- 生长倍率按「浇水那天」的季节算，跨季最后一晚仍按旧季，行为可预期。
- 雪不浇灌是刻意的冬季小挑战，和「反季慢」叠加但不过分（冬有当季菠菜）。
- 色板只染草地 / 树 / 花，土壤 / 水 / 建筑保持 constant，避免整图失真。

**新增模块** `seasons.ts`：推导 / 天气 / 倍率 / 色板集中一处，`render.ts` 与 `game.ts` 都只读它。

## v2.6 节日（已实现）

用户拍板：加简单节日。核心命题：**给四季加期待感**，且不破坏「每天都要干活」的节奏。

| 季节 | 节日 | 效果 | 加速的是 |
| --- | --- | --- | --- |
| 春 | 🌱 播种祭 | 种子半价 | 投入 |
| 夏 | 🎆 夏日祭 | 体力消耗减半 | 劳作 |
| 秋 | 🌾 丰收祭 | 出货 +50% | 变现 |
| 冬 | ✨ 星霜祭 | 产出品质 +1 星 | 提质 |

**设计取舍**：
- **只在当天有效，不累计**。若允许「攒着等节日卖」，会诱导玩家拖着一周不玩，与「每天照料」的核心冲突。
- 四个节日各加速一个环节（投入 / 劳作 / 变现 / 提质），而不是都给钱——这样每个节日提示的是「今天该做什么」，不是「今天能刷钱」。
- 品质 +1 对钓鱼 / 作物 / 动物产物**统一生效**，封顶 5 星。

**实现接法**：`festivalEffects(day)` 返回 `{seedMult, staminaMult, sellMult, qualityBonus, festival}` 一个对象，四处消费：
- `seedPrice()` → 商店与购买（显示划线原价 + 半价标签）
- `actionCost` / `animalCost` → 体力
- `sellLines` / `sellAll` → 金额（面板同步显示加成提示）
- 收获 / 挤奶捡蛋 / 收线 → 品质

**提示链**：睡前预告明天的节日 → 当天 HUD 徽章（呼吸动画）→ 出货面板标注加成 → 节日过后睡前告知「明年再见」。

## 0. 现状诊断

当前版本里，"工具"其实不存在，只有一个全局数字：

```ts
state.tool: number  // 0 铜 / 1 银 / 2 金 / 3 秘银
```

它同时作用于开垦和浇水，本质是一把万能升级品。同理，"物品"也不存在：

- 种子 = 一张 `{ turnip: 6, potato: 0 }` 的计数表
- 作物 = 收获后直接进 `basket` 这个隐形数组，走到出货箱一键清空
- 动作 = 面朝地块按空格，系统自动判断是开垦 / 播种 / 浇水，玩家没有任何选择权

**结论**：工具体系要成立，必须先有"物品"这个实体；工具必须先成为可持有、可切换、可损耗、可升级的**东西**，然后才谈得上体系。

---

## 1. 设计原则

1. **工具改变的是打字的手感，不只是数值。**
   如果银锄头只是"体力 -10%"，那它只是一行配置表，玩家不会记得自己换了工具。
2. **背包是仓库，快捷栏是手边。**
   两者必须分离。收拾东西在背包，干活在快捷栏，不能每做一件事都开背包翻找。
3. **摩擦必须有出口。**
   任何"你拿错工具了"的时刻，都要用自动切换或明确提示化解，而不是让玩家茫然地按空格。
4. **新增的复杂度必须换回可见收益。**
   加了材料系统，就必须有新的动作（砍树、挖石、割草）和新的东西可做，不能只是多一层币。

## 2. 物品模型

```ts
type ItemKind = 'seed' | 'crop' | 'material' | 'tool' | 'consumable';

interface ItemStack {
  id: string;          // 'seed.turnip' | 'crop.tomato' | 'mat.wood' | 'tool.axe'
  kind: ItemKind;
  qty: number;
  quality?: number;    // 仅 crop，1~5
}
```

### 堆叠规则

| 类别 | 上限 | 说明 |
| --- | --- | --- |
| 种子 | 99 | 按作物种类堆叠 |
| 作物 | 99 | **按「作物 + 品质」分堆**，5 星萝卜和 1 星萝卜不混 |
| 材料 | 99 | 木材 / 石材 / 纤维 |
| 工具 | 1 | 每格一把，不可堆叠 |

作物按品质分堆会让同类作物最多占 5 格，这是一笔刻意的成本：**品质有价值，就得占地方**。

**拒绝操作 + 提示**，不消耗体力、不消耗时间。绝不静默丢失物品。

## 4. 快捷栏

8 格常驻屏幕右下，可用 `1` ~ `8` 直接选择，`Q` 循环。

- 工具放进去就是"手持"
- 种子放进去就是"手持种子"
- 空格 = 使用手持物作用于面前格子

**这是本次改动对操作的最大影响**：原来的 `1~7` 选种子会被快捷栏取代，种子要先从背包放进快捷栏。

初始快捷栏：`锄头` `水壶` `(空)` `(空)` `(空)` `(空)` `(空)` `(空)`。

### 自动切换规则

按空格时：

1. 手持物适用 → 直接执行
2. 不适用，但快捷栏里有适用的工具 → **自动切换并提示**「换成 锄头」
3. 不适用，且没有该工具 → 提示「需要锄头」并给出获取途径（订购箱）

自动切换可以在设置里关闭，给硬核玩家。默认开启，因为这是打字游戏，不是工具管理游戏。

## 5. 工具体系

### 六把工具

| 工具 | 作用目标 | 体力 | 时间 | 词库示例 |
| --- | --- | --- | --- | --- |
| 🪓 锄头 hoe | 未开垦的土 | 4 | 10 | hoe / dig / plow / till / furrow / loosen |
| 🚿 水壶 can | 已播种的作物 | 2 | 10 | water / soak / drench / sprinkle |
| 🪓 斧头 axe | 树 | 6 | 20 | chop / split / fell / hack / cleave |
| ⛏ 镐 pickaxe | 岩石 | 7 | 25 | mine / quarry / smash / crack / strike |
| 🌾 镰刀 sickle | 杂草 | 2 | 5 | cut / mow / trim / slash |
| 🎣 钓竿 rod | 水面 | 5 | 30 | cast / reel / hook / land |

初始持有：锄头、水壶。其余四件在订购箱出售（斧 400G / 镐 500G / 镰 200G / 竿 350G）。

### 等级

每把工具**独立升级**，Lv1~Lv4（铜 / 银 / 金 / 秘银）：

| 等级 | 效果 |
| --- | --- |
| Lv1 铜 | 基础 |
| Lv2 银 | 容错 +1（打错仍算完美） |
| Lv3 金 | 时限 +25%，体力 ×0.9 |
| Lv4 秘银 | 专属能力（见下表） |

### 秘银专属能力（这把工具"变了"的时刻）

| 工具 | 秘银效果 |
| --- | --- |
| 锄头 | 一次开垦面前 3 格（3 个词连打） |
| 水壶 | 一次浇灌相邻 2 格 |
| 斧头 | 一击砍倒（不必 3 连击） |
| 镐 | 弱点暴击，掉落翻倍 |
| 镰刀 | 一次割掉周围 3 格杂草 |
| 钓竿 | 咬钩窗口从 1.2 秒放宽到 2 秒 |

### 升级配方

| 升级 | 金币 | 材料 |
| --- | --- | --- |
| 银 | 600 | 木材 ×8（斧/镐额外要石材 ×10） |
| 金 | 1800 | 石材 ×20 + 对应银工具 |
| 秘银 | 4200 | 木材 ×30 + 石材 ×30 + 对应金工具 |

材料必须先去砍树挖石，**升级路线天然把玩家推去用新工具**，这是这次扩展的核心节奏。

## 6. 打字模式：六种手感

这是"工具体系"真正的价值所在。每把工具的打字节奏都不同：

| 工具 | 模式 | 具体规则 |
| --- | --- | --- |
| 锄头 | 单次 | 一个词，标准判定 |
| 水壶 | 单次 | 一个词，成功后水流拖尾动画 |
| 斧头 | **三连击** | 同一个词连打 3 次；每命中一次树皮裂痕加深一级 |
| 镐 | **重击** | 一个长词；时限 -20%，容错为 0；命中时屏幕震动、碎石四溅 |
| 镰刀 | **快打串** | 3 个 2~3 字母短词连续打，每个只有 2.5 秒 |
| 钓竿 | **反应** | 抛竿（打 `cast`）→ 等待咬钩（随机 1~4 秒）→ 咬钩后 1.2 秒内按空格 → 再打 `reel` |

钓竿是唯一一个"等待 + 瞬间反应"的节奏，和农活的持续输入形成对比，适合放在碎片时间。

---

## 7. 资源节点

有工具就必须有靶子，否则斧头镐头无处可用。

| 节点 | 数量 | 击打次数 | 产出 | 刷新 |
| --- | --- | --- | --- | --- |
| 树 | 地图固定 12 棵 | 3 击 | 木材 2~4 | 砍倒后 3 天（树桩 → 小树 → 成树） |
| 岩石 | 地图固定 8 块 | 3 击 | 石材 2~3 | 5 天 |
| 杂草 | 每天随机 5~8 丛 | 1 击 | 纤维 1~2 | 每天刷新 |

杂草长在空地和未开垦的土地上，**会占据地块**，妨碍开垦。于是"每天割草"成为例行工作，镰刀有了日常用途。

## 8. UI 改动

## 9. 数据模型与存档迁移

```ts
interface ToolState {
  id: ToolId;
  owned: boolean;
  tier: 1 | 2 | 3 | 4;
}

interface GameState {
  // 新增
  bag: ItemStack[];              // 定长数组，null/空槽用 null
  bagSize: 16 | 24 | 32;
  hotbar: (HotbarRef | null)[];  // 长 8，HotbarRef = {type:'tool',id} | {type:'item',id}
  tools: Record<ToolId, ToolState>;
  autoSwitch: boolean;
  // 移除
  // seeds, basket, tool, selectedSeed
}
```

### 迁移 v1 → v2

1. `state.tool` 的等级 → 赋给锄头和水壶（其余工具为未持有）
2. `seeds` → 背包中的 seed 堆叠
3. `basket` → 背包中的 crop 堆叠（按品质合并）
4. 快捷栏默认放入锄头、水壶
5. 存档 `version: 2`；读到 v1 存档时自动转换，转换后立即覆盖保存

老存档玩家的钱包和进度不丢，这是硬要求。

## 10. 分期

| 版本 | 内容 |
| --- | --- |
| **v2.0** | 物品模型 · 背包 · 快捷栏 · 锄头/水壶/斧头/镐 · 树/岩石/杂草 · 木材/石材/纤维 · 工具购买与银级升级 · 存档迁移 |
| v2.1 | 镰刀 · 钓竿与反应式打字 · 金/秘银专属能力 · 工具耐久与修理 |
| v2.2 | 制作台（自己造工具）· 矿洞地图 · 动物 |

**建议 v2.0 就到这里**，因为它已经包含了一个完整的"采集 → 材料 → 升级 → 更强工具"闭环。镰刀钓竿和耐久可以被砍到 v2.1 而不破坏闭环。
